## 1. الخلاصة في سطرين

ربط Vercel بالمستودع **يتطلب تصريح وصول من مالك المستودع**. المستودع يخص **ريان**، وتطبيق Vercel على GitHub مثبَّت في نطاق **عبدالرحمن**. فلا يظهر المستودع في قائمة الاستيراد أصلًا.

**المطلوب: خطوة واحدة من ريان.** التفاصيل في §6.

---

## 2. ⚠️ تحذير حرج — مصيدة الاستنساخ

> ### إذا أدخلت رابط المستودع يدويًا في Vercel، **لا تضغط `Create`**

عند إدخال `https://github.com/RayanAlDwlah/dallal` في حقل Vercel، **لا يظهر خطأ**. بل تُعرض شاشة تبدو سليمة:

```text
New Project
  Cloning from GitHub        RayanAlDwlah/dallal   main
  Git Scope: Dem4t   /   Private Repository Name: dallal
  [ Create ]
```

**هذا مسار Clone لا Import.** الضغط على `Create` يُنشئ **مستودعًا ثانيًا** باسم `Dem4t/dallal` كنسخة، ويربط النشر **بالنسخة لا بمستودع الفريق**.

| العطب | الأثر |
|---|---|
| مستودع ثانٍ | يخالف قرار «مستودع واحد مشترك» صراحةً |
| النشر من النسخة | محمد وريان يدفعون في مستودع، والنشر من مستودع آخر |
| انفصال الفريق | برانشات وPRs موزّعة على مستودعين |

**لم يُضغط `Create`. لم يُنشأ أي مستودع ولا أي مشروع Vercel.** الكلمة الوحيدة التي تفرّق بين الصحيح والكارثة هنا هي **`Cloning`** في أعلى الشاشة.

## 4. السبب الجذري

```text
تطبيق Vercel على GitHub مثبَّت في نطاق:   Dem4t          ← حساب عبدالرحمن
المستودع المطلوب يخص:                      RayanAlDwlah   ← حساب ريان
```

**Vercel لا يرى مستودعًا لا يملك تصريح وصول إليه.** وتثبيت GitHub App على حساب شخص آخر يتطلب إذنه.

**كون عبدالرحمن `collaborator` بصلاحية كتابة لا يكفي.** صلاحية الكتابة تسمح بالدفع والـPRs، لكن **تثبيت تطبيقات GitHub يتطلب `admin` على المستودع** — وهي عند مالكه.

> **هذا اعتماد تقني لم يكن ظاهرًا وقت التخطيط.** `GITHUB_PLAN.md` أسند `S0-05` لعبدالرحمن لتوزيع حمل Sprint 0 عن ريان — وهو سبب سليم، لكنه لم يأخذ في الحساب أن الربط يحتاج صلاحية على المستودع.

### 11.3 السبب — مُشخَّص ومُعاد إنتاجه، لا مُفترَض

**`next/font/google` يجلب الخطوط من `fonts.googleapis.com` أثناء `next build` نفسه.** `app/fonts.ts` يطلب `IBM Plex Sans Arabic` و`IBM Plex Sans`، فإذا عجز مضيف البناء عن الوصول، يسقط البناء كاملًا.

**كيف تحقّقنا:** بناء ناجح محليًا يكتب ملفات `.woff2` مجلوبة من `fonts.gstatic.com` داخل `.next/` — وهذا وحده يثبت وجود طلب شبكة أثناء البناء. ثم أُعيد البناء مع حجب المنفذ، فأنتج توقيع الفشل نفسه:

```text
> Build error occurred
Error: Turbopack build failed with 2 errors:
Error: next/font: error: Failed to fetch IBM Plex Sans from Google Fonts.
```

خروج `1`، ومدّة قصيرة تطابق الـ ٢٠ ثانية المرصودة.

> **قيد على هذا التشخيص:** **سجلّ البناء الخام من Vercel لم يُقرأ** — الحساب المتاح للجلسة لا يملك وصولًا إلى نطاق `rayan-saleh1`. التشخيص مبني على توقيع الخطأ المؤكَّد من صاحب الفرع + إعادة إنتاج مطابقة محليًا. إن أظهر السجل الحقيقي سببًا آخر، فهذا الإصلاح **لازم وغير كافٍ**.

### 11.4 الإصلاح — مطبَّق ومدفوع ✅

استبدال `next/font/google` بـ `next/font/local` مع حزمتَي `@fontsource` (رخصة `OFL-1.1`)، فتصل ملفات الخطوط مع `npm ci` ولا يجري البناء أي اتصال بطرف ثالث.

**تُحقِّق منه:** `npm ci` نظيف ثم بناء **مع حجب Google Fonts** → نجاح، خروج `0`، ٨ مسارات.

### 11.5 ⚠️ بند جديد — رابط المعاينة محجوب بـ Deployment Protection

**البناء اتصلح، لكن المعاينة لا تُفتح.** فحص الرابط:

```text
GET https://dallal-cafxxfsso-rayan-saleh1.vercel.app
302 → 307 (X-Matched-Path: /api/sso) → 200
<html lang="en-US" class="… geistsans … dash">
```

`lang="en-US"` وخطوط Geist وصنف `dash` — أي **صفحة دخول Vercel**، لا تطبيق دلال. ولا أثر لكلمة «دلال» ولا `lang="ar"` في الجسم.

**السبب:** خاصية **Deployment Protection** مفعّلة على المشروع، فكل من ليس مسجّلًا في نطاق `rayan-saleh1` يرى جدار الدخول.

**لماذا يهم:** §9 من هذه الوثيقة تفترض أن «روابط المعاينة تعمل للجميع» — وهذا **غير صحيح حاليًا**. وبدونه لا يمكن تنفيذ `CP-2` (اختبار المتصفحين) ولا `V-3`، لأن المراجعين لا يفتحون المعاينة أصلًا.

**الحل — خطوة واحدة عند ريان:** إعدادات مشروع `dallal` ← **Deployment Protection** ← تعطيل الحماية على المعاينات، أو إضافة **Protection Bypass**.
